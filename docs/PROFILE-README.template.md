<!--
  Eligibility rules
  ================
  Which projects may be named in the profile, and what a link to them points
  at. Prose only — no live links below, because writing an example repo URL
  here would make the template itself a policy violation.

  * A PUBLIC repository links to its github.com/<owner>/<repo> url. Every
    visitor can open it, so there is no reason to link anywhere else.

  * A PRIVATE repository WITH a live public website links to the WEBSITE url
    only — never the repository url. A private repo url 404s for every single
    visitor, so linking it advertises a dead end and makes the profile look
    broken. The website is the public artifact; it is the thing to link.

  * A PRIVATE repository WITHOUT a website is omitted entirely. Not the repo
    url, not a placeholder, not a "coming soon" line. There is nothing to
    link that works, so the project does not appear in the profile at all.

  * A FORK is omitted. A fork is someone else's project; linking it claims
    work that is not yours. Link the upstream project instead, if that
    project is eligible under the rules above.

  Result: every link in the profile resolves to something a stranger can
  actually open.
-->
